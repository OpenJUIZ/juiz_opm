# 0009 opm_model はコアと図だけを型にし、他の名前空間は解釈せずに保って書き戻す

- 状態: 採用(案。XML の名前空間と要素名は [0006](0006-xml-format.md) と同じく Dori 先生の返事次第)
- 日付: 2026-11-07

## 背景

roadmap の Step 4 として、[metamodel.md](../../spec/metamodel.md) の型と、[xml.md](../../spec/xml.md) の交換形式の読み書きを Rust のクレート opm_model にする。xml.md §13 で「検査器の誤りの書き方と、警告と誤りの区別の細目」を Step 4 に残していた。

## 決めたこと

詳細は [spec/xml.md](../../spec/xml.md) §14。

1. **Cargo の workspace をリポジトリの根に置き、クレートは `crates/` に置く。** 最初は opm_model だけ。依存は XML の読み取りの roxmltree だけにし、書き出しは自前で書く。
2. **型はメタモデルの表を写す。** Thing は Object と Process の別を型で持ち(State は Object だけ、duration は Process だけ)、リンクは 1 つの型に種類(13 種)と、種類によって付く属性(modifier、from_state、ordered、tag など)を持つ。種類と属性の組み合わせの誤りは型ではなく検査で見る。コードで組んだモデルも同じ検査に通せるようにするため。
3. **他の名前空間の属性と要素は、解釈せずに id を持つ要素ごとに保つ。** juiz の注釈もここに入り、opm_model は juiz を知らない。書くときは読んだ並びのまま戻す(xml.md §8 の「できるだけ残して書き戻す」)。juiz の注釈の意味と J1〜J13 は Step 7 の juiz_opm が見る。
4. **読み手は形だけを見て、最初の誤りで止まる。** 知らない要素・属性、必須の属性の欠け、列挙と数の値を誤りにする。参照の解決と整形式の規則は読み手では見ない。子要素の順は見ない(XSD が見る)。
5. **検査器はコアの規則をすべて見る。** XSD が見る規則(C1〜C4 など)も含めて C1〜C12 を見る。値の形(id、名前、多重度、版)は F1〜F4 とする。C8 だけを警告にし、ほかは誤りにする。誤りは「規則の番号、要素の id、英語の文」の組で返す。
6. **XSD の表に足りない点は、近い規則の番号で見る。** effect 以外に付いた from_state・to_state は C5、aggregation 以外の ordered と tagged 以外の tag は C6、構造リンクを束ねた Fan は C11、Appearance の隠す State がその Thing の State でないものは C10。
7. **往復は「モデルが等しい」ことと「書いた文字が安定する」ことで確かめる。** 読む → 書く → 読むで同じモデルになり、2 回書いた文字が同じであること。注釈・空白・属性の並び・改行の位置は保たない。例 XML 3 つでこれを確かめ、書いた文書が XSD に通ることも CI で確かめる。

## 理由

- juiz を知らないコアの道具でも juiz の注釈が落ちないことが、交換形式として要る(xml.md §8)。注釈の意味を opm_model に入れると、juiz 以外の拡張を足すたびにコアが変わる。
- XSD 1.0 で見られない規則が残るため、検査器は要る。どうせ要るなら XSD の規則も含めて全部見たほうが、XSD なしで組んだモデルを確かめられる。
- 誤りに番号を付けると、OPL の検査器(Step 5)と juiz の検査器(Step 7)が同じ書き方で揃えられる。

## 影響

- Step 5 の opm_opl と Step 7 の juiz_opm は opm_model の型を使い、誤りも同じ形(規則の番号と id)で返す。
- tests/xml/check/ に「XSD に通るが検査器が誤りにする」例を置く。scripts/validate_xml.py はこれらが XSD に通ることも確かめる。
